================================================================================
PART 2: SUBSYSTEM DESIGN & RESPONSIBILITIES
================================================================================

--------------------------------------------------------------------------------
1. LOCAL SYSTEM PURPOSE (Primary Business Engine)
--------------------------------------------------------------------------------
The src/local/ directory holds the commercial logic and transactional features.
It manages:
* Product items presentation and dynamic loading.
* Catalog filter views and storefront grid rendering (Store Page).
* Page-specific styles and scripts for commercial views.
* REST APIs, Service layer, and JPA Repositories for the Product entity.
* The application main entry point (Plus33EuropeApplication.java).

--------------------------------------------------------------------------------
2. GLOBAL SYSTEM PURPOSE (Shared Website Platform Engine)
--------------------------------------------------------------------------------
The src/global/ directory holds the platform elements, layouts, and utilities.
It manages:
* Single Page Application (SPA) shell, dynamic routing, and asset handling.
* Shared layout components hardcoded in index.html: Navbar, Footer.
* Global features: AI Chatbot (Paris Pony), Franchise candidacy portal,
  Journal magazine, Store Locator, Rewards dashboard, About chronicle.
* Central application configuration (application.properties), Spring Security
  rules, database seeding via CommandLineRunner (DatabaseSeeder.java),
  and cross-cutting utilities: GlobalExceptionHandler, DtoMapper, AppConstants.
* Design system tokens and global CSS shared across all pages.

--------------------------------------------------------------------------------
3. MODULAR MONOLITH PATTERN
--------------------------------------------------------------------------------
Both subsystems compile into a single Spring Boot application JAR. The build is
unified by the build-helper-maven-plugin which registers both src/local/java and
src/global/java as source roots. The pom.xml resource declarations map all HTML,
CSS, JS, and asset folders from both subsystems into the correct
static/* classpaths within the final target/classes/ directory.

PART 3: DEEP-DIVE FILE-BY-FILE PURPOSE MAP
================================================================================

--------------------------------------------------------------------------------
A. ROOT WORKSPACE CONFIGURATIONS
--------------------------------------------------------------------------------
* pom.xml
  Purpose: Maven Build Descriptor.
           - Spring Boot parent: 3.5.14
           - Java version: 21
           - Spring Boot Admin version: 3.5.8
           - Dependencies: spring-boot-starter-web, spring-boot-starter-data-jpa,
             spring-boot-starter-security, spring-boot-starter-mail,
             spring-boot-starter-oauth2-client, spring-boot-starter-cache,
             spring-boot-starter-thymeleaf, spring-boot-starter-validation,
             spring-boot-admin-starter-server, thymeleaf-extras-springsecurity6,
             h2 (runtime), lombok (optional), spring-boot-devtools (runtime),
             spring-boot-docker-compose (runtime), spring-boot-starter-test (test),
             spring-security-test (test)
           - Plugins: build-helper-maven-plugin 3.5.0 (registers both java source
             roots), spring-boot-maven-plugin (excludes lombok from fat jar),
             maven-compiler-plugin (with Lombok annotation processor path for both
             compile and test-compile executions)
           - Resource declarations: maps application.properties to classpath root;
             maps src/local/html, src/local/css, src/local/js, src/local/assets
             to static/local/*; maps src/global/html/index.html to static/;
             maps all other src/global content (excluding application.properties,
             java/, and html/index.html) to static/global/*

* compose.yaml
  Purpose: Docker Compose stub file. Currently declares an empty services block
           with no active containers defined. Spring Docker Compose integration
           is explicitly disabled in application.properties.

* .vscode/launch.json
  Purpose: Defines two VS Code Java launch configurations both targeting the
           plus33-europe project. One targets the canonical main class at
           com.plus33.europe.local.Plus33EuropeApplication, the other targets
           com.plus33.europe.Plus33EuropeApplication (legacy fallback entry).

* .vscode/settings.json
  Purpose: Enables automatic Java null analysis and triggers workspace builds
           automatically when pom.xml changes
           (java.configuration.updateBuildConfiguration = automatic).

* .gitignore
  Purpose: Excludes target/, Maven wrapper jar, IDE-specific files (.idea, .iws,
           .iml, .ipr, STS files, NetBeans files), and the .vscode/ directory.

* .mvn/wrapper/maven-wrapper.properties
  Purpose: Pins Maven Wrapper to Apache Maven 3.9.15 via distribution URL.
           wrapperVersion is 3.3.4.

* .github/workflows/deploy.yml
  Purpose: CI/CD pipeline triggered on push to the main branch. Connects to the
           production server via SSH using appleboy/ssh-action@v1.2.0. On the
           remote host it: navigates to the deploy directory, runs git fetch and
           git reset --hard origin/main, makes mvnw executable, runs
           ./mvnw clean package -DskipTests, then restarts the plus33 systemd
           service via sudo systemctl restart plus33.

* src/global/js/router.js
  Purpose: Lightweight client-side SPA router (363 lines, 14KB).
           Defines the ROUTES map: { '/', '/franchise', '/find-us',
           '/journal', '/store', '/about', '/rewards', '/product/:id' }.
           Each route entry contains: fragment (HTML path or null for home),
           css (stylesheet path to lazy-load), title (document title string),
           init() (async function that dynamic-imports the page module and
           calls the mount function), destroy() (cleanup function stored
           as window._[page]Cleanup).
           The home route (/) uses null fragment because the home page HTML
           is baked into index.html. A _homeSnapshot captures the baked DOM
           on boot for back-navigation restoration.
           Navigation lifecycle (10 steps): destroy current page →
           transition out (page-transitioning class, 280ms) → pushState →
           fetch/inject fragment or restore home snapshot → load CSS once →
           update document.title → mark active nav links → scroll to top →
           transition in (page-entering class, 500ms) → call init(params).
           Route matching supports exact matches and dynamic segments (:id).
           Error fallback renders an editorial 404 block with Return Home link.
           Exposes window.plus33Router = { navigate } for external calls.

--------------------------------------------------------------------------------
A. PRODUCT API (/api/store)
--------------------------------------------------------------------------------
GET /api/store/products
  Description:    Returns all products or filters by category.
  Authentication: None (permitAll)
  Query Params:   ?category={string} — optional. Values: hot-coffee, iced-coffee,
                  retail, desserts, merchandise, signature, all (or omit)
  Response 200:   JSON Array of ProductDTO objects
  ProductDTO fields: id, name, description, price, category, origin, roast,
                     notes, imagePath, badge

GET /api/store/products/{id}
  Description:    Returns a single product by its numeric ID.
  Authentication: None (permitAll)
  Path Params:    {id} — Long (product primary key)
  Response 200:   JSON ProductDTO
  Response 404:   No body (HTTP 404 NOT FOUND)

--------------------------------------------------------------------------------
B. JOURNAL API (/api/journal)
--------------------------------------------------------------------------------
GET /api/journal/stories
  Description:    Returns all 14 seeded journal stories.
  Authentication: None (permitAll)
  Response 200:   JSON Array of JournalStoryDTO objects
  JournalStoryDTO fields: id, title, category, dateString, imagePath, excerpt,
                          readTime, subtitle, featured

--------------------------------------------------------------------------------
C. FRANCHISE API (/api/franchise)
--------------------------------------------------------------------------------
POST /api/franchise/apply
  Description:      Submits and persists a franchise candidate application.
  Authentication:   None (permitAll)
  Content-Type:     application/json
  Request Body:     FranchiseApplicationDTO JSON
    { name*, email*, phone*, city*, capital, background }
    (* required fields validated server-side)
  Response 200 OK:  { success: true, message: "...", applicationId: Long,
                      candidateName: String }
  Response 400:     { success: false, message: "Validation failed: ..." }
  Response 500:     { success: false, message: "Internal database error ..." }

--------------------------------------------------------------------------------
D. CHATBOT API (/api/chatbot)
--------------------------------------------------------------------------------
POST /api/chatbot/ask
  Description:    Returns a keyword-matched reply from the Atelier Barista.
  Authentication: None (permitAll)
  Content-Type:   application/json
  Request Body:   { message: String }
  Response 200:   { reply: String }
  Logic:          Keyword → reply constant mapping (see ChatbotServiceImpl).
                  Empty/null message returns default greeting.

PART 10: ARCHITECTURE OVERVIEW
================================================================================

--------------------------------------------------------------------------------
A. OVERALL ARCHITECTURE: MODULAR MONOLITH + SPA
--------------------------------------------------------------------------------
PLUS33 Europe is a modular monolith: a single deployable Spring Boot JAR that
internally organizes code into two distinct subsystems (local and global) with
clear separation of concerns. The frontend is a Single Page Application (SPA)
built with Vanilla HTML5, CSS3, and ES6 JavaScript — no framework overhead.

  Client Tier:   Vanilla HTML/CSS/JS + GSAP 3.12.5 + ScrollTrigger + Leaflet 1.9.4
  SPA Layer:     Custom client-side router (router.js, History API)
  Server Tier:   Java 21 + Spring Boot 3.5.14 + Spring Security + Spring Data JPA
  ORM:           Hibernate with H2 in-memory database
  Build:         Apache Maven 3.9.15 via Maven Wrapper

--------------------------------------------------------------------------------
B. LAYER ARCHITECTURE
--------------------------------------------------------------------------------
  Controller → Service Interface → Service Implementation → Repository → H2 JPA

  * Controllers receive HTTP requests, validate minimally, delegate to services.
  * Services handle business logic and delegate DB operations to repositories.
  * Repositories are Spring Data JPA interfaces auto-implemented by Hibernate.
  * DtoMapper converts between entity objects and DTO response envelopes.
  * GlobalExceptionHandler intercepts exceptions and produces clean JSON errors.

--------------------------------------------------------------------------------
C. PACKAGE ORGANIZATION
--------------------------------------------------------------------------------
  com.plus33.europe.local.*          Local subsystem packages (Product domain)
  com.plus33.europe.global.*         Global subsystem packages (platform domain)
  com.plus33.europe.global.config    Security, database seeder, SPA redirector
  com.plus33.europe.global.constants Chatbot reply string constants
  com.plus33.europe.global.controller REST controllers (Chatbot, Journal, Franchise)
  com.plus33.europe.global.dto       DTO envelopes for all API responses
  com.plus33.europe.global.exception Custom exception types and global handler
  com.plus33.europe.global.model     JPA entities and non-JPA domain objects
  com.plus33.europe.global.repository JPA repositories
  com.plus33.europe.global.service   Service interfaces and implementations
  com.plus33.europe.global.util      DtoMapper static utility
  com.plus33.europe.local.controller ProductRestController
  com.plus33.europe.local.dto        ProductDTO
  com.plus33.europe.local.model      Product entity
  com.plus33.europe.local.repository ProductRepository
  com.plus33.europe.local.service    ProductService interface + impl

--------------------------------------------------------------------------------
D. REQUEST LIFECYCLE
--------------------------------------------------------------------------------
Browser → URL request
  If SPA route: Spring WebController forwards to /index.html
  index.html renders: splash screen, navbar, baked home content, footer, chatbot
  router.js boots, reads current path, restores home or fetches fragment
  SPA navigation: router intercepts click → transition → fetch HTML fragment →
    inject into #app → lazy-load page CSS → call page init() module
  API calls: page JS fetches REST endpoint → Spring controller → service →
    repository → H2 → response JSON → DOM update

--------------------------------------------------------------------------------
E. DATA FLOW
--------------------------------------------------------------------------------
  Startup: DatabaseSeeder seeds 27 products + 14 journal stories into H2
  Store page: JS → GET /api/store/products → Spring → H2 → ProductDTO[] → JS renders grid
  Product detail: JS → GET /api/store/products/{id} → Spring → H2 → ProductDTO → JS renders detail
  Journal: JS → GET /api/journal/stories → Spring → H2 → JournalStoryDTO[] → JS renders magazine
  Franchise form: JS → POST /api/franchise/apply → Spring validates → H2 save → JSON response
  Chatbot: JS → POST /api/chatbot/ask → Spring keyword match → JSON { reply } → chat bubble
