================================================================================
PART 2: SUBSYSTEM DESIGN & RESPONSIBILITIES
================================================================================

--------------------------------------------------------------------------------
1. LOCAL SYSTEM PURPOSE (Primary Business Engine)
--------------------------------------------------------------------------------
The src/local/ directory holds the commercial logic and transactional features.
It manages:
* Product items presentation and dynamic loading.
* Curriculum-based filters and storefront views (Catalog).
* Specific styles and scripts for commercial grids.
* APIs, Services, and JPA Repositories relative to transactional models.

--------------------------------------------------------------------------------
2. GLOBAL SYSTEM PURPOSE (Shared Website Platform Engine)
--------------------------------------------------------------------------------
The src/global/ directory holds the platform elements, layouts, and utilities.
It manages:
* Single Page Application (SPA) state, dynamic asset handling, and routing.
* Shared layouts and responsive elements (Navbar, Footer, CSS Variables).
* Global components (AI Chatbot, Franchise candidacy, Boutiques mapper).
* Central application configurations, Spring Security rules, seeder processes,
  and cross-cutting utilities (Exception handlers, custom DTO mappers).

PART 3: DEEP-DIVE FILE-BY-FILE PURPOSE MAP
================================================================================

--------------------------------------------------------------------------------
A. ROOT WORKSPACE CONFIGURATIONS
--------------------------------------------------------------------------------
* pom.xml
  Purpose: Maven Build Descriptor. Imports Spring Boot starter models, configures
           properties (Java 21, Spring Boot 3.5), registers src/local/java and
           src/global/java dynamically using the build-helper-maven-plugin,
           and defines precise packaging target paths so resources copy to target/classes/.

* .vscode/launch.json
  Purpose: Instructs VS Code's Java extension to run com.plus33.europe.Plus33EuropeApplication
           explicitly with correct classpaths, neutralizing launch conflicts.

* .vscode/settings.json
  Purpose: Enables automatic workspace rebuilds on pom.xml changes.
